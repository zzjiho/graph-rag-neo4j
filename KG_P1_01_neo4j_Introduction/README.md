# KG_P1_01 Neo4j Introduction (섹션 1, 2)

> 강의: Neo4j 환경 설정, Cypher 기본

## 이 강의의 학습 목표

이 강의를 마치면 다음을 할 수 있어요.

1. 노드, 레이블, 속성, 관계가 각각 무엇인지, 그리고 `(p:Person {name: "홍길동"})` 한 줄을 부분별로 읽을 수 있어요.
2. 그래프 DB가 RDB(MySQL, PostgreSQL)와 데이터를 담는 방식에서 어떻게 다른지 설명할 수 있어요.
3. `MATCH`, `CREATE`, `MERGE`, `SET`, `REMOVE`, `DELETE`로 데이터를 찾고, 만들고, 고치고, 지울 수 있어요.
4. `CREATE`가 중복을 만들고, 관계 달린 노드를 `DELETE`하면 에러가 나는 함정을 피할 수 있어요.

읽기 전에 이 질문 하나를 머리에 두고 보면 좋아요. **"RDB의 테이블, 행, 컬럼, FK는 그래프 DB에서 각각 무엇이 될까?"**

## 한눈에 보기

그래프 DB는 데이터를 점(노드)과 화살표(관계)로 저장해요. 그리고 Cypher는 그 점과 화살표를 **그림 그리듯 글자로 적어서** 찾고 고치는 언어예요. 그래서 괄호 `( )`는 노드, 화살표 `-[ ]->`는 관계를 뜻해요.

```
(홍길동) ──KNOWS──▶ (김철수)
 노드      관계       노드
```

처음 질문에 대한 답을 먼저 표로 놓고 시작할게요.

| RDB | 그래프 DB | 예 |
|---|---|---|
| 테이블 | 레이블 | `:Person` |
| 행 | 노드 | `(홍길동)` |
| 컬럼 | 속성 | `{name: "홍길동", age: 30}` |
| FK + JOIN | 관계 | `-[:KNOWS]->` |
| SQL | Cypher | `MATCH ... RETURN` |

실습 환경은 두 가지예요. **AuraDB**는 Neo4j의 클라우드 버전이라 설치 없이 쓸 수 있고, 무료 티어는 노드와 관계 수에 상한이 있어요(강의 기준 노드 5만, 관계 17.5만). 그리고 **uv**는 pip보다 빠른 파이썬 패키지, 가상환경 관리 도구인데, `uv.lock`이 설치된 버전을 고정해 줘요.

## 1. 괄호 하나가 노드 하나

```
(p:Person {name: "홍길동", age: 30})
```

| 부분 | 이름 | 뜻 |
|---|---|---|
| `p` | 변수 | 이 쿼리 안에서만 쓰는 이름표 |
| `:Person` | 레이블 | 노드의 종류 (사람) |
| `{name: "홍길동", age: 30}` | 속성 | 그 노드가 가진 값 |

연락처 앱으로 비유하면 연락처 카드 한 장이 노드이고, "가족"이나 "회사" 같은 그룹이 레이블이고, 카드에 적힌 이름과 나이가 속성이에요. 그러니까 노드가 속성을 **가지고** 있는 거지, 노드가 곧 속성인 건 아니에요. "홍길동"은 노드에 적힌 이름 값이고, 노드는 그 사람 전체예요.

그런데 RDB와 비교하면 다른 점이 두 가지 있어요.

- **노드 하나에 레이블을 여러 개 붙일 수 있어요** (`:Person:Employee`). 반면 RDB는 한 행이 테이블 하나에만 속하니까, 직원이기도 한 사람을 표현하려면 `employee` 테이블에 행을 하나 더 만들고 FK로 이어야 해요.
- **스키마가 미리 정해져 있지 않아요.** 그래서 같은 레이블이어도 노드마다 속성이 달라도 돼요. RDB는 테이블 스키마로 컬럼을 미리 정해 두고, 값이 없으면 NULL로 두죠.

```cypher
(:Person {name: "홍길동", age: 30, email: "hong@example.com"})
(:Person {name: "김철수", age: 28})   // email이 없으면 그냥 안 적어요
```

참고로 Neo4j Browser 왼쪽의 "Nodes (4)" 아래에 보이는 `City`, `Person`은 노드가 아니라 **레이블 목록**이에요. 괄호 안의 4가 노드 총 개수고요. `Person`을 누르면 `MATCH (n:Person) RETURN n LIMIT 25`가 실행돼서 실제 노드들이 동그라미로 그려져요.

## 2. 관계에는 방향이 있다

관계는 항상 한쪽에서 다른 쪽으로 향해요. 다만 만들 때와 찾을 때 규칙이 달라요.

- **만들 때는 방향이 필수예요.** `CREATE`에서 방향 없는 관계는 만들 수 없어요.
- **찾을 때는 방향을 무시해도 돼요.** `-[:KNOWS]-`처럼 화살표 없이 쓰면 양쪽 방향을 다 찾아요.
- 관계 타입은 대문자로 쓰는 게 관례예요 (`KNOWS`, `LIVES_IN`).
- `-[r:FRIENDS|KNOWS]->`처럼 `|`로 이으면 둘 중 아무거나(OR)예요.

## 3. 주요 구문은 SQL의 CRUD와 짝이 맞는다

| 구문 | 하는 일 | SQL로 치면 |
|---|---|---|
| `MATCH` + `WHERE` + `RETURN` | 패턴으로 찾아서 거르고 돌려주기 | `SELECT ... WHERE` |
| `CREATE` | 무조건 새로 만들기 | `INSERT` |
| `MERGE` | 있으면 찾고, 없으면 만들기 | upsert |
| `SET` | 속성 바꾸기, 추가하기 | `UPDATE` |
| `REMOVE` | 속성이나 레이블 떼기 | `UPDATE ... SET col = NULL` |
| `DELETE` / `DETACH DELETE` | 지우기 / 관계까지 같이 지우기 | `DELETE` |

그리고 결과를 다듬을 때는 SQL처럼 `ORDER BY`(정렬), `LIMIT`(개수 제한), `SKIP`(건너뛰기)을 써요.

```cypher
MATCH (p:Person)-[:KNOWS]->(f:Person)
WHERE p.name = "홍길동" AND f.age >= 30
RETURN f.name
```

이 쿼리를 말로 풀면 "홍길동이 아는 사람(f) 중에서 30살 이상인 사람의 이름"이에요. 즉 `MATCH`에 그린 모양을 찾고, `WHERE`로 거르고, `RETURN`으로 돌려주는 흐름이에요.

## 4. 함정 두 가지

### CREATE는 중복을 만든다

`CREATE`는 같은 홍길동이 이미 있어도 또 만들어요. 노트북 주석에도 "동일한 노드가 이미 존재해도 중복 생성되므로 주의"라고 적혀 있죠. 그래서 실무에서는 `MERGE`를 훨씬 많이 써요. 그리고 `ON CREATE SET`을 붙이면 새로 만들어질 때만 속성을 넣어요.

```cypher
MERGE (p:Person {name: "홍길동"})
ON CREATE SET p.age = 30
```

### 관계 달린 노드는 그냥 DELETE가 안 된다

관계가 붙어 있는 노드를 `DELETE`로 지우면 에러가 나요. 관계만 남으면 화살표 한쪽 끝이 허공을 가리키게 되니까요. 그래서 관계부터 지우거나, `DETACH DELETE`로 관계까지 한 번에 지워요.

```cypher
MATCH (p:Person {name: "홍길동"})
DETACH DELETE p
```

## 5. 정리하며 기억할 것

- 괄호는 노드, 화살표는 관계예요. Cypher는 이 모양을 글자로 그려서 찾는 언어예요.
- 레이블은 RDB의 테이블, 속성은 컬럼, 관계는 FK와 JOIN 자리에 와요. 다만 레이블은 여러 개 붙일 수 있고 스키마가 고정돼 있지 않아요.
- 관계는 만들 때 방향이 필수고, 찾을 때는 방향을 생략할 수 있어요.
- 중복이 걱정되면 `CREATE` 대신 `MERGE`, 관계 달린 노드를 지울 때는 `DETACH DELETE`예요.

## 다음이랑 어떻게 이어지나

여기서는 관계를 1홉(관계 하나)만 건너는 패턴만 다뤘어요. 다음 [Cypher 고급](../KG_P1_02_neo4j_cypher_advanced)에서는 여러 홉을 건너가는 가변 길이 경로(`*1..3`), 최단 경로, 집계, `WITH`를 배워요. "친구의 친구"처럼 몇 단계 떨어진 관계를 찾는 게 그래프 DB를 쓰는 진짜 이유라서, 여기서 배운 `MATCH` 패턴이 거기서 길어져요.
