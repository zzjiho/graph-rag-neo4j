# KG_P1_02 Cypher Advanced (섹션 3)

> 강의: Cypher 고급 (소셜 네트워크 데이터)

## 이 강의의 학습 목표

이 강의를 마치면 다음을 할 수 있어요.

1. 가변 길이 경로(`*1..3`)로 여러 홉 떨어진 노드를 찾고, 왜 최대 홉 수를 꼭 정해야 하는지 설명할 수 있어요.
2. `shortestPath`로 두 노드 사이의 가장 짧은 길을 찾고, 관계 타입을 안 정하면 왜 엉뚱한 길이 나오는지 설명할 수 있어요.
3. `GROUP BY` 없이 집계하는 규칙을 알고, `WITH`로 집계 결과를 다시 거를 수 있어요.
4. 같은 변수 재사용, 패턴 조건(`WHERE NOT ...`), 파라미터(`$`)를 섞어서 "친구 추천" 같은 쿼리를 만들 수 있어요.

읽기 전에 이 질문 하나를 머리에 두고 보면 좋아요. **"'홍길동의 1~3단계 친구'를 SQL로 짜면 어떻게 될까? 그리고 그래프 DB에서는?"**

## 한눈에 보기

솔직히 그래프 DB든 RDB든 데이터를 저장해 두고 쿼리로 꺼낸다는 점은 같아요. 그래서 이번 강의에서 배우는 집계는 RDB와 거의 똑같아요. 차이는 **관계를 여러 번 건너가야 할 때**만 드러나요. 그래서 이번 강의의 진짜 주인공은 가변 길이 경로와 최단 경로예요.

실습 데이터는 사람 8명, 관심사(Interest) 5개, 장소(Location) 4곳으로 된 소셜 네트워크예요. 관계는 `KNOWS`(친구), `LIKES`(좋아함), `VISITED`(방문, 평점 있음) 세 가지고요. 그중 친구 관계만 그려 보면 이래요.

```
            ┌──▶ 김철수 ──▶ 정소라 ──▶ 윤미래
            │                          ▲
  홍길동 ───┼──▶ 강대호 ───────────────┘
            │       │
            │       ▼
            └──▶ 이영희 ──▶ 박지성 ──▶ 최민수
                    │                  ▲
                    └──────────────────┘
```

## 1. 가변 길이 경로

관계 안에 `*`를 붙이면 "몇 홉을 건너가도 된다"는 뜻이에요. 홉은 관계 하나를 건너는 거고요. 지하철로 치면 "몇 정거장 안에 갈 수 있는 역 전부"를 찾는 셈이에요.

```cypher
MATCH (p1:Person {name: '홍길동'})-[:KNOWS*1..3]->(p2:Person)
RETURN DISTINCT p2.name
```

| 표기 | 뜻 | 홍길동 기준 |
|---|---|---|
| `*1` | 1홉 | 김철수, 강대호, 이영희 |
| `*2` | 정확히 2홉 | 정소라, 윤미래, 이영희, 박지성, 최민수 |
| `*1..3` | 1~3홉 전부 | 위 둘 + 3홉까지 |
| `*` | 제한 없음 | 이어진 사람 전부 |

여기서 꼭 알아 둘 점이 세 가지예요.

- **`*`(제한 없음)는 쓰지 않아요.** 데이터가 크면 경우의 수가 폭발해서 쿼리가 끝나지 않아요. 그래서 항상 `*..5`처럼 최대 홉 수를 정해요.
- **같은 사람이 여러 번 나와요.** 결과는 사람마다가 아니라 **길마다** 한 줄씩 나오거든요. 예를 들어 이영희는 1홉(홍길동→이영희)으로도, 2홉(홍길동→강대호→이영희)으로도 나와요. 그래서 사람만 보고 싶으면 `DISTINCT`를 붙여요.
- 관계에 변수를 붙이면(`-[r:KNOWS*1..3]->`) `r`은 관계 하나가 아니라 관계 **목록**이 돼요. 그래서 `size(r)`가 건넌 홉 수예요.

## 2. 최단 경로

지도 앱 길찾기처럼 "가장 적게 건너는 길 하나"를 찾아요.

```cypher
MATCH p = shortestPath((a:Person {name: '홍길동'})-[:KNOWS*..5]-(b:Person {name: '최민수'}))
RETURN [n IN nodes(p) | n.name] AS 경로
```

홍길동에서 최민수까지 가는 길은 세 개예요. 홍길동→이영희→최민수(2홉), 홍길동→이영희→박지성→최민수(3홉), 홍길동→강대호→이영희→최민수(3홉). 이 중 `shortestPath`는 2홉짜리 하나만 돌려줘요.

- `p = ...`로 길 전체를 받아 두고, `nodes(p)`로 길 위의 노드를, `length(p)`로 홉 수를 꺼내요.
- `[n IN nodes(p) | n.name]`은 파이썬 리스트 컴프리헨션과 같은 문법이에요.
- 가장 짧은 길이 여러 개여도 하나만 줘요. 전부 필요하면 `allShortestPaths`가 있다는 것만 알아 두면 돼요.

그런데 여기서 이 강의의 핵심 함정이 나와요. **관계 타입을 안 정하면 엉뚱한 길이 나와요.** `-[*]-`는 아무 관계나 타도 된다는 뜻이거든요. 실제로 실습 데이터에서 김철수와 박지성 사이를 이렇게 찾으면 "김철수 → 스포츠(관심사) ← 박지성"(2홉)이 최단으로 나와요. 둘이 친구로 이어진 길은 "김철수 – 홍길동 – 이영희 – 박지성"(3홉)인데도요. 그러니까 친구 관계로만 찾고 싶다면 `-[:KNOWS*]-`처럼 관계 타입을 꼭 정해야 해요.

## 3. 집계 함수

규칙은 하나예요. **Cypher에는 `GROUP BY`가 없고, `RETURN`에 집계 함수와 같이 적은 값이 자동으로 묶는 기준이 돼요.**

```cypher
MATCH (p:Person)
RETURN p.city AS 도시, COUNT(p) AS 사람수   // p.city가 묶는 기준
ORDER BY 사람수 DESC
```

- `RETURN COUNT(p)`만 쓰면 묶는 기준이 없으니까 전체 8명이 나와요.
- `RETURN p.city, COUNT(p)`로 쓰면 도시별로 묶여서 서울 3, 부산 2, … 처럼 나와요.

그런데 같은 "서울"도 두 가지 방법으로 셀 수 있어서 헷갈리기 쉬워요.

| 세는 방법 | 쿼리 | 뜻 |
|---|---|---|
| 속성으로 | `p.city = '서울'` | 서울에 **사는** 사람 (홍길동, 이영희, 강대호) |
| 관계로 | `(p)-[:VISITED]->(l:Location {city: '서울'})` | 서울 장소에 **가 본** 사람 |

그래서 도시별 사람 수에서 서울은 3명인데, Browser에서 경복궁을 눌러 보면 이영희와 최민수(대전에 삶)가 나와요. 즉 쿼리를 읽을 때는 "지금 속성을 보는지, 관계를 따라가는지"부터 확인해야 해요.

그리고 관계에도 속성이 있어요. 장소 평점은 사람이나 장소가 아니라 `VISITED` 관계에 붙어 있어서, 평균을 낼 때 `AVG(v.rating)`처럼 관계 변수에서 꺼내요.

## 4. WITH: 중간 결과를 다음 단계로

`WITH`는 중간 결과를 다음 단계로 넘기는 파이프예요. 주로 집계한 결과를 다시 거를 때 쓰는데, SQL의 `HAVING` 자리라고 생각하면 돼요.

```cypher
MATCH (p:Person)
WITH p.city AS 도시, AVG(p.age) AS 평균나이
WHERE 평균나이 >= 35
RETURN 도시, 평균나이
```

- `WITH` 뒤에는 **`WITH`에 적은 변수만 남아요.** 그래서 위 쿼리에서 `p`는 `WITH` 이후에 쓸 수 없어요.
- 같이 알아 둘 `OPTIONAL MATCH`는 패턴을 못 찾아도 그 행을 빼지 않고 null로 채워 둬요. SQL의 `LEFT JOIN`과 같아요. 예를 들어 "방문한 곳이 0개인 사람"도 결과에 남기고 싶을 때 써요.

## 5. 패턴 섞기와 파라미터

새 문법은 없어요. 지금까지 배운 걸 섞으면 돼요.

```cypher
// 홍길동과 관심사가 같은데 아직 친구가 아닌 사람 = 친구 추천
MATCH (p1:Person {name: '홍길동'})-[:LIKES]->(i:Interest)<-[:LIKES]-(p2:Person)
WHERE NOT (p1)-[:KNOWS]-(p2)
RETURN DISTINCT p2.name, i.name
```

- **같은 변수를 다시 쓰면 같은 노드예요.** `i`가 두 번 나오니까 "둘이 같은 관심사를 좋아한다"는 뜻이 돼요.
- **패턴 자체를 조건으로 쓸 수 있어요.** `WHERE NOT (p1)-[:KNOWS]-(p2)`는 "친구 관계가 없는"이라는 뜻이에요.
- 자기 자신이 섞여 나오면 `WHERE p1 <> p2`로 빼요.
- 더 나아가 최단 경로 + `WITH` + 집계를 섞으면 "홍길동에서 1단계 몇 명, 2단계 몇 명" 같은 거리별 사람 수도 한 쿼리로 구할 수 있어요.

값을 바꿔 가며 쿼리를 돌릴 때는 파라미터(`$`)를 써요. 쿼리 글자는 그대로 두고 값만 바꿔 넣는 거라서, 사용자 입력을 문자열로 이어 붙이지 않으니 Cypher 인젝션도 막혀요.

```python
graph.query(
    "MATCH (p:Person {name: $name})-[:KNOWS*1..2]->(f) RETURN DISTINCT f.name",
    params={"name": "홍길동"},
)
```

다만 레이블, 관계 타입, `*1..3`의 숫자는 파라미터로 바꿀 수 없어요. 그래서 이런 걸 바꿔야 하면 허용 목록으로 거른 값만 문자열로 넣어요.

## 6. 그래서 RDB랑 뭐가 다른데

이제 처음 질문에 답할 수 있어요. "홍길동의 1~3단계 친구"를 SQL로 짜면 재귀 쿼리(`WITH RECURSIVE`)를 쓰거나 단계마다 JOIN을 붙여야 해요. RDB는 관계를 FK로만 두고 조회할 때마다 JOIN으로 키를 맞춰 보는 반면, 그래프 DB는 관계 자체가 "다음 노드로 가는 길"로 저장돼 있어서 화살표만 따라가면 되거든요. 그래서 Cypher에서는 `*1..3` 한 줄로 끝나요.

| 이런 질문이 많으면 | 쓰는 것 |
|---|---|
| 주문, 결제, 정산처럼 테이블로 딱 떨어지는 정형 데이터 | RDB |
| 친구의 친구, 추천, A에서 B까지 어떻게 이어지나 | 그래프 DB |

## 7. 정리하며 기억할 것

- 가변 길이 경로는 항상 최대 홉 수를 정하고, 사람만 보려면 `DISTINCT`를 붙여요.
- 최단 경로나 가변 길이 경로에서는 관계 타입을 정해야 원하는 관계로만 길을 찾아요.
- `GROUP BY`는 없어요. 집계 함수와 같이 적은 값이 묶는 기준이에요.
- `WITH`는 파이프라서, 적은 변수만 다음 단계로 넘어가요. 그리고 `OPTIONAL MATCH`는 `LEFT JOIN`이에요.
- 값은 `$` 파라미터로 넣고, 레이블이나 관계 타입은 허용 목록으로 걸러요.
